В этом руководстве собраны правила выпуска обновлений приложения **PARTPOCKET (N.ECO Part Storage)**, работы с сервером PocketBase и рекомендации по устранению сбоев.

## 1. Стандартный выпуск обновлений (In-App APK Update via GitHub Actions)

Используется для всех релизов (изменения UI, исправления багов, обновление логики, нативные модули).

### Пошаговый процесс:
1. Внесите необходимые изменения в код проекта.
2. Проверьте сборку веб-бандла:
   ```bash
   npm run generate
   ```
3. Обновите версию в `package.json` (например, `"version": "1.1.9"` ➔ `"version": "1.1.10"`).
4. Зафиксируйте изменения в git и создайте аннотированный тег:
   ```bash
   git add .
   git commit -m "feat/fix: описание изменений, bump vX.Y.Z"
   git tag -a vX.Y.Z -m "Описание релиза для пользователей"
   git push origin main
   git push origin vX.Y.Z
   ```
5. GitHub Actions автоматически запустит workflow `.github/workflows/build-apk.yml`. Сборка занимает ~2.5 минуты, создаст релиз на GitHub и прикрепит подписанный постоянным ключом APK.
6. **(Рекомендуется для ускорения раздачи в РФ):** Загрузите готовый APK в коллекцию `app_updates` PocketBase (поле `apk_file`), чтобы клиенты скачивали его напрямую с московского VPS VDSina.
7. **Результат у клиентов:** При открытии приложения (или нажатии кнопки «Проверить обновления» в Настройках) пользователь видит окно обновления, нажимает «Скачать и обновить» и приложение обновляется в 1 клик с сохранением всех данных склада.

## 2. Скрипт deploy_ota.mjs (Архивный)

Скрипт `scripts/deploy_ota.mjs` (`npm run deploy:ota`) упаковывает `dist.zip` и загружает его в PocketBase как `bundle_zip`.  
Без установленного нативного плагина распаковки на Android-устройствах данный архив клиентами не применяется. Не используйте этот скрипт как самостоятельный метод выпуска обновлений.
* Заменены системные иконки приложения или виджеты рабочего стола.

### Пошаговый процесс:
1. Увеличьте версию в `package.json` (например, `"version": "1.1.5"`).
2. Зафиксируйте изменения в git и отправьте тег:
   ```bash
   git add .
   git commit -m "Релиз 1.1.5: описание изменений"
   git tag v1.1.5
   git push origin main
   git push origin v1.1.5
   ```
3. После пуша тега `v*` GitHub Actions автоматически запустит workflow `.github/workflows/build-apk.yml`.
4. Сборка занимает около 3–4 минут. Готовый подписанный файл `neco-part-storage.apk` будет прикреплен к разделу **Releases** репозитория на GitHub.
5. Для синхронизации OTA-пакета выполните также:
   ```bash
   npm run deploy:ota -- "Релиз 1.1.5"
   ```

## 3. Обслуживание базы данных PocketBase

### Хранение старых обновлений:
* **Нужно ли хранить все старые записи в `app_updates`?**  
  **Нет.** Приложение запрашивает только **одну** самую свежую запись с максимальным `build_number`.
* Архив `bundle_zip` является полным автономным веб-бандлом, а не диффом/патчем.
* Вы можете спокойно удалять старые промежуточные записи через панель администрирования PocketBase (`http://195.209.213.115:8090/_/`). При удалении записи PocketBase автоматически удаляет файл zip с диска, освобождая место.
* Рекомендуется оставлять **1 последнюю актуальную версию** (или максимум 1 предыдущую для возможности ручного отката).

## 4. Решение сетевых проблем и траблшутинг

### Симптом: «Нет связи с сервером» при регистрации или входе
1. **Проверьте VPN на мобильном устройстве:**  
   Большинство VPN-сервисов в РФ блокируют прямой доступ к IP-адресам российских хостингов (VDSina) или нестандартные порты (8090). **Отключите VPN** и повторите попытку.
2. **Проверьте доступность сервера в мобильном браузере:**  
   Откройте `http://195.209.213.115:8090/_/` в Google Chrome на телефоне. Если панель открывается — физическая связь в порядке.
3. **Mixed Content / HTTP в Android WebView:**  
   Начиная с версии APK **v1.1.4**, в проекте включены:
   * Нативный сетевой стек `CapacitorHttp` (обход браузерных блокировок).
   * Схема `androidScheme: 'http'` + `cleartext: true`.
   * Файл `network_security_config.xml` с явным разрешением IP сервера.
   * `WebSettings.MIXED_CONTENT_ALWAYS_ALLOW` в `MainActivity.java`.  
   Если на устройстве пользователя стоит старая сборка APK (ниже v1.1.4), ему необходимо один раз установить обновленный APK поверх старого.
