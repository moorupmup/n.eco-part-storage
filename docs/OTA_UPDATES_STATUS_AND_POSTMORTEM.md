# История и статус системы обновлений (OTA Postmortem & Guide for AI Agents)

> [!IMPORTANT]
> **Критическое правило для всех ИИ-агентов:**  
> **В приложении в настоящий момент НЕТ работающего «тихого» OTA-обновления (без установки APK)!**  
> Любое обновление клиентской части (даже правка одного слова в интерфейсе) требует сборки и распространения подписанного APK через GitHub Actions. Запрещено заверять пользователя, что изменения «уже прилетели по воздуху», без выпуска APK.

## 1. Контекст инцидента (Релиз v1.1.9, ноябрь 2026)

### Что произошло:
1. По запросу пользователя в коллекцию `users` на сервере PocketBase было добавлено поле `last_login`, а в интерфейс и стор `stores/auth.ts` — логика фиксации и отображения даты входа.
2. ИИ-агент, прочитав устаревшие записи в `docs/ARCHITECTURE.md` и `docs/DEPLOYMENT.md`, сообщил пользователю, что данное обновление можно выкатить «по воздуху» (Live OTA) без переустановки APK.
3. Агент запустил `scripts/deploy_ota.mjs` (`npm run deploy:ota`), который скомпилировал веб-бандл и загрузил `bundle_zip` в таблицу `app_updates` PocketBase.
4. **Результат:** На телефоне пользователя после перезапуска приложение продолжало отображать версию `v1.1.8`, обновление не применилось и не было обнаружено.

## 2. Анализ причин сбоя (Root Cause Analysis)

### Причина 1. Нативный плагин OTA был удален в v1.1.6
В ранних версиях (v1.1.0 – v1.1.5) в проект был установлен плагин `@capgo/capacitor-updater`.  
Однако на реальных Android-устройствах этот плагин привел к критическому сбою: **при запуске приложения возникал бесконечный цикл перезагрузки и мерцания WebView**.  
В коммите `f1cc48d` (автор *moorupmup*, релиз `v1.1.6`):
* Плагин `@capgo/capacitor-updater` был **полностью удален** из `package.json`, `capacitor.config.ts`, `composables/useAppUpdater.ts` и `layouts/default.vue`.
* Механизм обновлений был переведен на **скачивание полноценного APK внутри приложения**.

### Причина 2. Ограничения операционной системы Android
Все файлы веб-приложения (HTML, JS, CSS) компилируются внутрь APK-файла в каталог `android/app/src/main/assets/public/`.  
В Android этот каталог доступен **строго только для чтения**. Без нативного плагина-перехватчика системный WebView не имеет технической возможности подменять встроенные ассеты на скачанные из интернета.

### Причина 3. Несоответствие скрипта деплоя и клиентского кода
В коде проверки обновлений на клиенте ([`composables/useAppUpdater.ts`](file:///c:/Users/pumpu/Desktop/n.eco-part-storage/composables/useAppUpdater.ts), строка 107) прописано условие:
```typescript
if (recVer && compareVersions(recVer, cleanCurrent) > 0 && item.apk_file)
```
Скрипт `deploy_ota.mjs` загружал в PocketBase поле `bundle_zip`, оставляя поле `apk_file` пустым. Из-за этого клиентское приложение на телефоне полностью игнорировало такую запись как некорректную.

### Причина 4. Рассинхронизация документации с кодом
В файлах `docs/ARCHITECTURE.md` и `docs/DEPLOYMENT.md` сохранялись устаревшие инструкции по использованию `npm run deploy:ota` для «99% обновлений». Это ввело ИИ-агента в заблуждение.

## 3. Актуальная архитектура обновлений (Как это работает сейчас)

Сейчас в проекте используется надежная схема **In-App APK Update**:

```
                              ┌─────────────────────────────────────────┐
                              │            Внесение изменений           │
                              │           (в UI, базу или Android)      │
                              └────────────────────┬────────────────────┘
                                                   │
                                                   ▼
                                        Bump версии в package.json
                                        git commit & git tag vX.Y.Z
                                                   │
                                                   ▼
                                        git push origin main --tags
                                                   │
                                                   ▼
                                       GitHub Actions CI Workflow
                                       (.github/workflows/build-apk.yml)
                                                   │
                                     ┌─────────────┴─────────────┐
                                     ▼                           ▼
                        Сборка подписанного APK      Прикрепление к GitHub Release
                                     │
                                     ▼
                     (Опционально / Рекомендуется)
                     Загрузка APK в PocketBase app_updates (apk_file)
                                     │
                                     ▼
                     Приложение на телефоне обнаруживает релиз,
                     скачивает APK в кэш и открывает диалог установки в 1 клик
```

### Порядок проверки клиентом:
1. Клиент обращается к серверу PocketBase в коллекцию `app_updates`:
   * Ищет запись с максимальным `build_number`.
   * Требует `recVer > currentVersion` и обязательное наличие **`apk_file`**.
2. Если в PocketBase записи с APK нет или сервер недоступен:
   * Клиент обращается к GitHub API (`/repos/moorupmup/n.eco-part-storage/releases/latest`).
   * Находит прикрепленный `neco-part-storage.apk`.
3. При обнаружении версии открывается модальное окно [`components/AppUpdateModal.vue`](file:///c:/Users/pumpu/Desktop/n.eco-part-storage/components/AppUpdateModal.vue).
4. Пользователь нажимает **«Скачать и обновить»**:
   * Через `@capacitor/filesystem` APK скачивается в кэш устройства (`Directory.Cache/update.apk`).
   * Через `@capacitor-community/file-opener` вызывается системный установщик Android.
   * Все данные склада (IndexedDB / SQLite) и сессия авторизации сохраняются.

## 4. Четкий чеклист для ИИ-агентов при выпуске любого релиза

Если пользователь просит выпустить обновление (даже минимальное):

1. **Поднять версию:**
   В [`package.json`](file:///c:/Users/pumpu/Desktop/n.eco-part-storage/package.json) увеличить `version` (например, `1.1.9` ➔ `1.1.10`).
2. **Проверить сборку локально:**
   ```bash
   npm run generate
   ```
3. **Зафиксировать изменения и отправить тег:**
   ```bash
   git add .
   git commit -m "feat/fix: краткое описание изменений, bump vX.Y.Z"
   git tag -a vX.Y.Z -m "Описание релиза для пользователей"
   git push origin main
   git push origin vX.Y.Z
   ```
4. **Дождаться сборки APK в GitHub Actions (~2.5 минуты):**
   * Следить за статусом: `https://github.com/moorupmup/n.eco-part-storage/actions`
5. **Загрузить APK в PocketBase (для ускорения раздачи в РФ):**
   После появления APK в GitHub Releases скачать его и обновить запись в PocketBase `app_updates` с прикреплением файла в поле `apk_file`.
6. **Сообщить пользователю:**
   Предложить открыть приложение и нажать «Проверить обновления» в Настройках, либо дождаться автоматического уведомления.

## 5. Перспективы возврата тихих OTA-обновлений

Если в будущем возникнет задача вернуть «тихие» обновления по воздуху (без окна установки APK):
1. **Потребуется внедрить стабильный нативный плагин:**
   * Либо новая стабильная версия `@capgo/capacitor-updater` с обязательным изолированным тестированием на Android, чтобы исключить регресс бага с мерцанием экрана.
   * Либо кастомное нативное решение (загрузка бандла в `context.getFilesDir()` и перенаправление базового URL `BridgeWebViewClient`).
2. **Первый релиз с плагином ОБЯЗАТЕЛЬНО должен быть установлен через полный APK:**
   Устройства с версиями `v1.1.6 – v1.1.9` не смогут принять тихое обновление, пока на них не будет установлен APK с включенным нативным OTA-модулем.
